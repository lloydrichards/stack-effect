# Package tests

- Use the manifest's `exports` to identify public entry points. Put tests in `test/<PublicModule>.test.ts` and group related contracts with `describe`. Keep a single file per public module or contract when the cases share a runner and environment. Split for a distinct runner, environment, or global setup. Keep shared fixtures in `test/fixtures/`.
- Import public modules. Run the real owner and assert returned data, typed errors, files, events, or resource lifetime. Pin order, exact text, and interaction counts when callers depend on them. Use the nearest platform boundary for faults or controlled responses so the service's behavior remains real.
- For Scaffold, start with a small Selection and test catalog, then build phase inputs through the public pipeline. Hand-build an invalid phase value to test its rejection. Use the memory filesystem for repository state. Use the shared fault helper and trigger on an observable path, platform operation, or call count. Check that the fault fired and assert the typed error and resulting repository state. See [Apply](../../../../packages/scaffold/test/Apply.test.ts).
- Import `assert`, `describe`, and `it` from `@effect/vitest`. Use `it.effect` by default. For typed failures, use `Effect.flip` and check the tag and identifying data. Use `Effect.exit` when asserting a defect or interruption.
- Use `TestClock` for time and explicit readiness signals for concurrency. For scope cleanup, wait until work starts, close its owning scope, then check the resource or fiber is released. For protocols, control requests and test the relevant wire behavior. See the [catalog loader tests](../../../../packages/scaffold/test/Catalog.test.ts).
- Share conformance cases when several adapters promise the same observable behavior. Keep platform-specific cases beside the adapter that owns them.
- Use runtime tests for runtime behavior. Use compile-time assertions for deliberate inference or assignability guarantees that ordinary type-checking would miss. `typetest/` has no dedicated runner in this repository. Check packaging through the owning package's existing verification entry point.
